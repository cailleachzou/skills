# 真实工作流场景

> 6 个工作流，从单一技能到多技能串联，由简入深。

---

## 工作流 1：PDF 表格提取到 Excel

**复杂度**：★☆☆☆☆（单一技能）

**场景**：你有一份 PDF 里的报价表，需要提取到 Excel 里做进一步计算。

**涉及技能**：`pdf` → `xlsx`

**步骤**：

1. 用 `pdf` 技能提取表格数据
   ```
   帮我把这份 PDF 里的表格提取出来：C:/项目资料/报价单.pdf
   ```

2. Claude 会用 pdfplumber 提取表格，输出结构化数据

3. 用 `xlsx` 技能把数据写入 Excel
   ```
   把提取的表格数据写入 Excel，加上财务配色和公式
   ```

**预期输出**：一个格式化的 .xlsx 文件，带表头样式和求和公式。

## 工作流 2：CAD 图纸翻译

**复杂度**：★★☆☆☆（单一技能，多步骤）

**场景**：拿到一份中文 DWG 图纸，需要翻译成英文给海外客户。

**涉及技能**：`dwg`

**步骤**：

1. 查看图层列表
   ```
   帮我看一下这份 DWG 有哪些图层：C:/项目资料/平面图.dwg
   ```

2. 提取中文文字
   ```
   提取所有中文文字并翻译成英文
   ```

3. 导出翻译后的 DXF
   ```
   把翻译后的文字写回图纸，导出为 DXF
   ```

**预期输出**：一份新的 .dxg 文件，中文标注已替换为英文。

## 工作流 3：网页内容提取 → Obsidian 笔记

**复杂度**：★★☆☆☆（双技能串联）

**场景**：看到一篇技术文章，想保存到 Obsidian 笔记库里。

**涉及技能**：`defuddle` → `obsidian-markdown`

**步骤**：

1. 用 `defuddle` 提取网页内容
   ```
   帮我把这篇文章提取成干净的 Markdown：https://example.com/article
   ```

2. 用 `obsidian-markdown` 格式化并保存
   ```
   保存到我的 Obsidian 笔记库，加上 frontmatter 和标签
   ```

**预期输出**：一个带 YAML frontmatter、wikilinks 的 .md 文件，已存入 Obsidian vault。

## 工作流 4：项目资料 → 方案文档

**复杂度**：★★★☆☆（三技能串联）

**场景**：拿到一堆项目资料（PDF、图片、网页），需要整理成一份正式的技术方案。

**涉及技能**：`markitdown` → `docx` → `diagram-skill`

**步骤**：

1. 用 `markitdown` 批量提取资料文字
   ```
   把 C:/项目资料/ 文件夹里的所有 PDF 和 Word 文件转成 Markdown
   ```

2. 用 `docx` 生成方案文档
   ```
   基于提取的内容，生成一份技术方案 Word 文档：
   - 封面 + 目录
   - 系统概述、设计方案、设备清单
   - 用 Tendo 品牌模板
   ```

3. 用 `diagram-skill` 补充图表
   ```
   画一张系统架构图和一张项目甘特图，嵌入方案文档
   ```

**预期输出**：一份完整的 .docx 方案文档，含目录、架构图、甘特图。

## 工作流 5：完整方案包

**复杂度**：★★★★☆（四技能串联）

**场景**：投标场景，需要从原始资料生成一整套方案包（Word + PPT + 图表）。

**涉及技能**：`markitdown` → `docx` → `diagram-skill` → `pptx`

**步骤**：

1. 资料提取（markitdown）
   ```
   把 C:/投标资料/ 里的所有文件转成 Markdown
   ```

2. 方案文档（docx）
   ```
   生成技术方案 Word 文档，包含：
   - 公司简介、项目理解、技术方案、实施计划、售后服务
   - 用 Tendo 信纸模板
   ```

3. 图表补充（diagram-skill）
   ```
   生成以下图表：
   - 系统架构图（architecture-beta）
   - 项目甘特图（gantt）
   - 网络拓扑图（flowchart）
   ```

4. 汇报 PPT（pptx）
   ```
   基于方案文档，生成一份 15 页的汇报 PPT：
   - 封面、目录、公司简介、方案亮点、技术架构、实施计划、报价汇总
   - 用 Tendo 品牌配色
   ```

**预期输出**：
- `技术方案.docx` — 完整方案文档
- `汇报.pptx` — 汇报演示文稿
- 若干 Mermaid 图表代码块

## 工作流 6：Superpowers 全流程开发

**复杂度**：★★★★★（开发工作流）

**场景**：你要开发一个新的 Claude Code 技能，从需求到上线。

**涉及技能**：superpowers 系列（brainstorming → writing-plans → TDD → ...）

**步骤**：

1. **brainstorming** — 需求探索
   ```
   我想做一个新的技能，把微信聊天记录导出成 Markdown
   ```
   Claude 会问你一系列问题，帮你明确需求和设计。

2. **writing-plans** — 制定计划
   ```
   基于刚才的设计，写一个实现计划
   ```

3. **test-driven-development** — 先写测试
   ```
   按计划开始实现，先写测试
   ```

4. **systematic-debugging** — 遇到 bug 时
   ```
   测试报错了：xxx
   ```

5. **verification-before-completion** — 完成前验证
   ```
   跑一下所有测试，确认通过
   ```

6. **requesting-code-review** — 代码审查
   ```
   帮我 review 一下代码
   ```

7. **finishing-a-development-branch** — 收尾
   ```
   测试通过，准备合并
   ```

**预期输出**：一个完整的、经过测试和审查的技能，已合并到主分支。

## 工作流组合原则

1. **线性流水线** — 上一步的输出是下一步的输入（如 PDF → 文字 → 文档）
2. **并行分支** — 多个独立任务同时进行（如同时生成图表和文档）
3. **条件跳转** — 根据中间结果决定下一步（如 OCR 失败则换用视觉识别）
4. **迭代优化** — 生成 → 审查 → 修改 → 再审查

掌握这 4 种模式，就能组合出任意复杂的工作流。
