# Unlimited-OCR 实测坑（2026-09-13，13 份证件/简历/证明 PDF）

一轮真实任务（入职材料 13 份，22 页扫描 + 14 页文字层）踩出来的。**这些坑不避开，
会得到一批「回执写成功、内容其实不可用」的产物。**

---

## 1. 多页 Base 模式把整页压进 1024 方形 → A4 有效只有约 88 DPI

`crop_mode=False`（即 `--pdf` 路径）走的是
`modeling_unlimitedocr.py:931`
```python
global_view = ImageOps.pad(image, (image_size, image_size), color=...)
```
`ImageOps.pad` **等比缩放塞进 1024×1024 方块**。300 DPI 栅格出来的 2480×3508 会被缩到
**724×1024** —— A4 那 8.26 英寸宽上只剩 724 px ≈ **88 DPI**。

**后果**：大字号（标题、姓名、印章）读得到，**小字号（证件号码、表格备注、字段标签）大片丢失**。

> ⚠️ **`--dpi` 调多大都没用。** 栅格 300 / 400 / 600 DPI 出来都是同一个 1024 方框。
> 实测一份护照页：读出了「中华人民共和国护照」「邹景焘」，却**一个字段标签都没读到**
> （`姓名/出生/签发/有效期/性别/国籍` 全缺），护照号也没读出。

判据：页面若含小字（证件、表格、票据），**默认模式大概率不够**。

---

## 2. `--image-size` 超过 1024 会崩，而且不是「更清晰」

想当然地把 `--image-size` 提到 2048 来提分辨率 —— **实测直接毁掉**：

| 页 | 2048 模式结果 |
| --- | --- |
| 银行卡页 | 119 字符，**中文 0**（纯噪声） |
| 护照页 | **0 字符** |
| 另一次 | 触发**长生成循环卡死**：CPU 满载、日志 5 分钟无输出、攥着 6.4 GB 显存不放 |

模型只在 `base_size=1024` / `image_size=640–1024` 这档训练过。**别越界。**

---

## 3. 会陷入不终止的生成循环，只能等 max_length 撞顶

多次复现，且**退出码 0、回执写「成功」**：

| 输入 | 产物 |
| --- | --- |
| 护照页 | `1. 2017年1月1日` × 45 |
| 护照页（另一种模式） | `希腊各国民` × 4 |
| 某退款单分块 | 32127 字符垃圾 |

单块可白烧 ~6 分钟（`max_length=32768` ÷ ~85 tok/s）。`no_repeat_ngram_size=35` /
`ngram_window` **拦不住**。

> ⚠️ **`ocr.report.md` 说「成功 22 失败 0」不等于内容可用。**
> 回执只判「有没有产物」，判不了「产物是不是垃圾」。
> **必须另做内容合理性判据**：字符数异常大/异常小、中文占比过低、单字符长重复。

---

## 4. 分块能提分辨率，但收益不稳定；重叠分块去重不可靠

把页面切块单独送模型 = 每块都进 1024 方框 → 有效分辨率约翻倍（88 → 160~210 DPI）。
实测**银行卡号就是这样才读出来的**。但：

- ⚠️ **重叠分块的去重不可靠**：相邻块在重叠带上的识别输出**并不一致**，
  按「最长行级后缀/前缀匹配」实测 **0% 命中**。拼回去要么重复、要么丢内容。
- 有的块会触发第 3 条的循环。

**更好的做法 —— 在空白处下刀**：按墨迹分布（低 DPI 渲染后逐行/逐列求 `255-灰度` 之和）
在目标位置附近找**墨迹最少的一行/一列**切。无重叠 → **直接顺序拼接即可，不需要去重**，
也不切断文字。

## 5. 「要不要 OCR」不能按图像覆盖率判断 —— 文字层完整就该用文字层

本次把一份学籍验证报告判成「需 OCR」，理由是图片覆盖 103%。**判错了**：
它的文字层是**完整的**，而 OCR 反而把 `之用途` 读成 `之间途`。

**判据是文字层本身是否完整可读**，不是图占多大。
（`page.get_images()` + `get_image_rects()` 算覆盖率在这里是误导性指标。）

---

## 6. 水印文字层会污染 pymupdf4llm 的表格；**redaction 会连坐正文**

社保参保证明自带一条水印文字层，pymupdf4llm 把它和表格单元格混在一起，
每个格子里都插了水印碎片。

⚠️ **不要用 `add_redact_annot()` 抹** —— 它是**按矩形**抹的，水印 bbox 往往压在表格格子上，
一擦就连正文一起削掉。实测：抹完只剩 470 字符，**正文全丢**。

✅ **按字体过滤 span**，再按坐标聚成行列自己拼表格。

**怎么定位水印字体**：按 `(font, size)` 分组，统计每组的
`span 数 / 不同文本数 / 最高重复次数 / 平均 span 宽`。
水印特征 = **span 少、平均宽度大、内容高度重复**。
（本次：表格数据是 `SimSun 8.0`（216 span、均宽 25pt、最高重复「已记账」×55）；
水印是 `STSong-Light 12.0`（27 span、均宽 219pt）。）

## 7. pymupdf4llm 会吐出成片的 `~~` 删除线伪影

本次体检报告有 **256 处** `~~`，但那些 span 的 `flags` **全是 0**（根本没有删除线标记）——
是 pymupdf4llm 的推断伪影，且会把词切断（`~~第一部~~ 分 报 ~~告阅~~ 读 ~~说明~~`）。

**修法**：去掉 `~~`，再把**中文字之间被拆散的空格**并回去：
```python
s = s.replace("~~", "")
s = re.sub(r"(?<=[一-鿿]) +(?=[一-鿿])", "", s)
```

## 8. 小模型对同一个小字段会给出**多个互相矛盾**的答案

同一份职位申请表，三轮读数给出：

| 字段 | 读数 1 | 读数 2 | 读数 3 | 真值 |
| --- | --- | --- | --- | --- |
| 姓名 | 邹圣燕 | 邵勇燕 | 邹景彦 | 邹景焘 |
| 身份证号 | …403X | …435X | …435X | …453X |

还编造过**图里根本不存在的文字**（护照页的「中华人民共和国驻德国大使馆建筑」）。

> ⚠️ **不要靠「再读一遍」来定真值 —— 多读几遍只会多几个候选。**
> 要靠**外部约束**：校验位、跨文件印证、自洽检查。

## 9. 校验位是最强判据，应当**前置**

| 对象 | 算法 | 本次效果 |
| --- | --- | --- |
| 身份证号 | GB 11643-1999 加权模 11 | 一举坐实 `…403X` 是错的（正确为 `…453X`） |
| 银行卡号 | Luhn | 19 位卡号通过 |
| 护照 MRZ | 护照号 / 出生日期 / 有效期**各有独立校验位** | 三个全过 → 该页关键字段可视为已确证 |

加权算法（MRZ 通用，字母 A=10…Z=35，`<`=0，权重 7-3-1 循环）：
```python
def mrz_cd(s):
    w=[7,3,1]; tot=0
    for i,c in enumerate(s):
        v = int(c) if c.isdigit() else (ord(c)-55 if c.isalpha() else 0)
        tot += v*w[i%3]
    return tot%10
```
**自洽检查**同样有用：身份证内嵌出生日期 ↔ 其他文件上的出生日期。

## 10. `run.sh` 的显存守卫是必需的，**别绕过**

权重实测 **6,672,547,120 字节 = 6363 MiB**（`model-00001-of-000001.safetensors`）。
门槛 `NEED_MIB=6600` 只留约 240 MiB 给激活值。实测空闲 6556 MiB 时被守卫正确拦下——
那个余量下轻则静默掉 CPU（慢十倍），重则 OOM 崩在 `try` 之外、连回执都不留。

---

## 11. OCR 进程可能不退出，攥着显存挡掉下一次运行

实测一次 `--image-size 2048` 的循环卡死进程，在**外层 shell 任务已报完成（退出码 0）之后
仍然活着**，占着 6.4 GB 显存。下一次 OCR 会被守卫挡下，而守卫的报错文案指向
「看还有谁占着卡」—— **很容易误判成别的程序在抢显存。**

排查：
```python
import psutil
for p in psutil.process_iter(['pid','name','cmdline']):
    cl = ' '.join(p.info['cmdline'] or [])
    if 'python' in (p.info['name'] or '').lower() and 'ocr.py' in cl:
        print(p.info['pid'], cl)
```
注意 venv 会起**父子两个 python**（`Scripts\python.exe` 拉器 + uv 的真实解释器），
两个都要清。杀完**轮询 `nvidia-smi` 直到显存真的回落**再重跑。

## 一句话总结

> **回执说「成功」只代表跑完了。**
> 默认模式对含小字的页面分辨率不足（~88 DPI）；调大 `--image-size` 会崩；
> 模型会循环、会编造；分块能救一部分但去重不可靠（改在空白处切）。
> **真值靠校验位 + 跨文件印证，不靠多读几遍。**

## 12. 复核阶段的三条教训（2026-09-13 二次逐份复查新增）

### 12.1 「再读一遍」不如「直接看图」—— 高价值字段直接读原图

整轮下来最强的判据不是任何 OCR 调参，而是**把原图交给主模型直接看**。同一批文档：

| 手段 | 护照号 | 身份证号 | 学历证书编号 |
| --- | --- | --- | --- |
| 整页 OCR（1024） | ✗ 输出循环垃圾 | ✗ 读成 20 位 | ✗ 读作 `…2108…` |
| 高清分块 OCR | ✗ 仍是循环垃圾 | ✗ | — |
| 400 / 600 DPI 定点裁剪 | ✗ | ✗ 读作 `…435X` | ✗ 读作 `…2105…` |
| **原图直读** | ✅ 且 MRZ 三个校验位全过 | ✅ 与户籍证明逐字一致 | ✅ `…2106…`，与发证月份吻合 |

**结论**：OCR 只用来**铺量**（把整页变成可检索文本）；
凡是要当事实用的字段（证件号、金额、日期、单位名、校名），**直接看原图**。
主模型读一次图就能拿全，比让 2B 级 OCR 反复重试强得多。

副作用要记住：看原图意味着**图像出本机**，与送云端是同一类风险，敏感件需用户明确知情同意。

### 12.2 批量替换必须**验证真的替换上了**，否则静默漏改

用脚本做批量修正时，`str.replace(旧, 新)` 找不到「旧」是**静默失败** ——
不报错、只是少改一处，而脚本照样打印「已修正 N 处」。本次实测踩到两回：

- 目标串**跨了换行**（住址在 PDF 里断成两行），而「旧」写成了不带换行的连续串 → 没替换上
- 修正表的字典键写成了**省略号占位符**（`"13_…参保证明…"` 这种手写简写）→ 整段待核对根本没生成

**做法**：
1. 替换完成后**再扫一遍所有「旧」串**，断言零残留 —— 本次正是靠这一步才发现 2 处漏网
2. `dict.get()` 查表要确认键是**真实值**（从数据里取），不是手写占位符
3. 校验位这类**可自证**的字段（身份证、银行卡）要跑一遍算法，`…403X` 就是被校验位逮住的

### 12.3 说明段必须与正文物理隔离，否则下次检查会误报

把「原读 → 修正」的对照写进产物里很有用（可审计），
但**必须放在带独立标题的小节里**（如 `### 修正说明`）。

本次终检脚本按关键词扫全文，把说明段里**故意保留的旧错误值**当成了「没改干净的正文错误」，
一口气误报 15 处。正确做法是检查脚本先按标题**切掉说明段**，再扫正文。
